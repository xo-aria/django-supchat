# Languages & RTL

The widget and the panel share one translation file: `supchat/static/supchat/i18n.js`.

| Code | Language | Direction | Status |
|---|---|---|---|
| `en` | English | LTR | maintained |
| `fa` | فارسی (Persian) | RTL | maintained |
| `ar` | العربية (Arabic) | RTL | community, needs native review |
| `tr` | Türkçe | LTR | community, needs native review |
| `es` | Español | LTR | community, needs native review |
| `de` | Deutsch | LTR | community, needs native review |
| `fr` | Français | LTR | community, needs native review |
| `ru` | Русский | LTR | community, needs native review |

Corrections from native speakers are very welcome.

## Choosing the language

- **Visitors:** the saved choice (🌐 button), then `SUPCHAT["LANGUAGE"]`, then `<html lang>`, then the browser language. The result must be one of `SUPCHAT["LANGUAGES"]`.
- **Operators:** the saved choice (🌐 button in the sidebar), then the browser language.

RTL languages flip the layout with CSS logical properties. Message text uses `dir="auto"`, so mixed Persian/English messages render correctly. Dates use the locale's calendar and digits through `Intl` (for example the Solar Hijri calendar for `fa`). The widget's screen corner (`POSITION`) does not flip.

## Adding a language

1. Add an entry to `META` in `i18n.js`: `xx: { name, native, dir, locale }`.
2. Add a `STRINGS.xx` block. Keys you don't translate fall back to English.
3. Add the code to `supchat.conf.LANGUAGES`, or override `i18n.js` in your project's static files.

A test checks that `en` and `fa` define the same keys and that every key used in the JavaScript exists.
